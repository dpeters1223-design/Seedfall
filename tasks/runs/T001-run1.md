## Lessons

1. **The implementer was the easy part.** Writing code from a precise contract worked first time, here and in the earlier benchmark.
2. **The critic was the weak link.** DeepSeek-Coder-V2-Lite repeatedly used `Assert.AreEqual(Vector3, Vector3, float)`, an overload that doesn't exist in NUnit. Even when explicitly told not to, it brought it back.
3. **Small models apply feedback partially.** They fix the first or loudest item and drop the rest, and their own "DEFECTS" self-reports are unreliable (false accusations, or an echo of the feedback).
4. **Because nothing compiled, the implementation was never actually tested.** A broken test file blocks the whole assembly, including the smoke test.

## Changes to try (step 9)

- **Lint before Unity.** Have a cheap script check the test file for known-bad patterns (such as `AreEqual(` with a Vector3 and a tolerance, a missing `using Seedfall.Core;`, or `[Ignore]`) and bounce it straight back with the exact line. That's seconds instead of a 15 s Unity run, and gives more precise feedback.
- **Give the critic a test helper.** Add `Seedfall.Tests.Shared.AssertV3.Near(expected, actual, tol)` to the project so the right way is also the easy way. Mention it in every critic prompt.
- **The controller writes the test list into the spec.** Name each test with its inputs and expected values, as the final retry did. The critic's job becomes "implement these tests and add attack cases", not "invent the tests".
- **Try swapping roles.** Run Qwen as the critic and DeepSeek as the implementer on the next attempt. The plan already calls for swapping.
- **Separate compile failures by author.** If only the test file fails to compile, temporarily run the implementer's code against a controller-written minimal test, so one builder's mistakes don't hide the other's.
