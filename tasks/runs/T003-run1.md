## Lessons

1. **The new shape works.** Sound tests up front, plus two independent tries, got a pass on the first round.
2. **One-error feedback is applied precisely.** Qwen changed exactly the line it was told to fix. That's a clear improvement on T001, where multi-point feedback was half ignored.
3. **Identical retries produce identical failures.** At temperature 0.2 with the same prompt, Qwen re-emitted the same broken line. When a builder repeats a failure, the orchestrator must change something on the next try: raise the temperature, ask for just the corrected line and splice it in, or hand that builder's slot to the other model.
4. **Mechanical errors (a missing `;`) could be fixed mechanically.** A tiny auto-fix step for trivial compiler errors, before spending a model call, is worth considering, but only for a short allowlist of errors.
5. **Specs can be wrong too.** The builder ignored an incorrect claim in the spec and did the right thing. The controller should treat a builder deviating from the spec as a signal to re-check the spec, not just as an error.
6. **Both builders have now produced correct code.** DeepSeek has done so once here, and Qwen did in the earlier T001 benchmark. Keeping two independent implementers is paying off.
